## 0.2.32：NapCat 登录过期后中间消息仍不被消费

**用户原话**：「napcat登录过期之后，中间的消息还是不会被langbot消费」。
这正是前一轮留下的开放项「NapCat 在线但 LangBot WS 断开不触发补拉」同源问题，
用户实测把它坐实了，不需要再拍板，直接修。

### 根因

旧 `BackfillService.tick()` **只靠 `offline → online` 边沿**触发。三类故障都没有这个边沿：

1. QQ 登录过期：NapCat 进程和 HTTP 服务照常跑，`get_status.online` 一直是 true，
   但 QQ 已经不推消息给 LangBot；
2. 重登落在两次 10s 探活之间，被采样漏掉；
3. LangBot 与 NapCat 之间的 WS 断开，NapCat 完全正常。

结果 `_was_online` 恒为 `True`，补拉永不执行。`get_status` 只能代表 OneBot 服务，
**不代表 QQ 账号登录态**。

### 实现（插件侧，Spring 不动）

- `core/napcat.py`：`online()` 兼容字段缺失（有 `online` 用 `online`，否则 `good`，
  再否则非空 data 就算在线——否则字段不叫这名会让 `_was_online` 永远 False，更难查）；
  新增 `account_online()` 调 `get_login_info`，`user_id > 0` 才算账号真登录。
- `core/backfill.py`：每轮**双探**，任一异常 / false 都置 `_was_online = False`；
  就绪时算 `edge`（恢复立即补）和 `sweep_due`（`napcat_backfill_sweep_s` 默认 300s
  周期兜底），`edge or sweep_due` 才跑。**边沿降级为加速信号，周期兜底才是保底**。
  `run_once()` 抛异常也在 `finally` 里写 `_last_pull_at`——否则 Spring 挂了会
  每 10s 全量扫 50 个会话的历史接口，容易触发风控。`_sweep_interval` 下限 30s。
- `core/config.py` / `manifest.yaml`：新增 `napcat_backfill_sweep_s`（默认 300，最小 30）。
- 补拉本身幂等（`dedupeKey = msg:<message_id>` + 游标 `GREATEST` 只进不退），
  重复跑只多几次本机 HTTP，**不会重复写日志、不会补发回复**。

> 设计决策：不改成常驻高频轮询去「抓」边沿，而是承认边沿不可靠、加低频无条件回查。
> 这样即使将来出现新的「无掉线边沿」故障形态，最多漏 300 秒的消息，不会永久停摆。

### 测试与回归

## 补齐「修改密码」前端入口

**起因**：用户问「登录功能中的密码登录是用什么登的」。查代码确认：不是 QQ 账号、
也没有 `sys_user` 表，是项目自带的单管理员账号——用户名 `app_setting.auth_username`
（默认 `admin`），密码来自 `AUTH_INITIAL_PASSWORD`，没配则后端随机生成 12 位、只在
首次启动日志 `log.warn` 打一次；BCrypt 哈希写 `app_setting.auth_password_hash`。
`credentials()` 只在哈希为空时初始化，**哈希一旦落库，再改环境变量不生效**。
登录还要图形验证码（Redis `auth:captcha:<id>` TTL 2 分钟，一次即删），
会话 `auth:session:<token>` TTL 30 分钟滑动续期。QQ 登录共用
`createSession(username)`，只借用户名、完全不碰密码哈希。

**发现的缺口**：后端 `POST /api/auth/password` 和 `src/api/auth.ts` 的
`changePassword()` 都在，但**没有任何页面调用**，改密码只能直接调接口或改库。
用户回「可以」，补一个表单。

**做法**（纯前端，不动后端 / 数据库 / 插件）：

- 新建 `src/views/PasswordView.vue`（`/password`）：旧密码 / 新密码 / 确认新密码三项，
  前端拦「< 6 位」「两次不一致」「新旧相同」，错误用 `errorField` 精确标到对应输入框
  的 `aria-invalid`；整个 card 是真 `<form>`，任意框回车都能提交。
- 成功链路：`changePassword()` → `logout()` 让**服务端当前会话也失效**（只清本地
  token 的话 Redis 那把还留 30 分钟）→ `clearToken()` → `toast.success` →
  `router.replace({ name:'login', query:{ changed:'1' } })`。
- `LoginView.vue`：读 `changed` 初值把默认页签切成「密码登录」（watch 有
  `immediate: true`，会自动拉图形验证码），并在页签下加一条持久成功提示。
  用 `--ok` 变量，别拿 `--accent-ink`（那是逾期/强调色）。
- `MoreView.vue`「系统」分组加入口（`KeyRound` 图标），`router/index.ts` 加路由。
- 页面文案明确两点：改的是兜底口令不是 QQ 密码；哈希落库后改环境变量无效。
  另如实说明**后端不会强踢其它已签发会话**，它们按 30 分钟 TTL 自然过期。

## 登录页图形验证码被裁切（第四轮截图反馈）

用户发截图：密码登录页验证码图片**首尾字符被切掉一半**，4 位码认不全。

**根因（纯 CSS，与后端无关）**：`AuthService.createCaptcha()` 用
`CaptchaUtil.createLineCaptcha(120, 40, 4, 20)` 生成 **120×40** 图片；
而 `LoginView.vue` 的 `.captcha-row` 第二列只有 **108px**，`.captcha` 高 42px、
`overflow: hidden`，`.captcha img` 又是 `object-fit: cover`。cover 取较大的缩放比
（42/40 = 1.05），把图放大到 126×42 后居中裁掉左右各 9px——正好切掉 4 位码的头尾。

**修法**：列宽 `108px → 120px` 与图片 1:1；`object-fit: cover → contain`
（即使后端以后改尺寸也只会等比缩小留白，不会再吃字符）；img 加 `display:block`
去掉基线间隙；按钮补 `title="看不清？点一下换一张"`（本来就能点刷新，但视觉上没提示）。
同时在 `design/api_contract.md` §16.1 钉死「120×40 / 必须 contain / 别改回 cover」，
避免后续改登录页样式时复发。

**验证**：`npm run build`（含 `vue-tsc`）通过。纯前端样式修复，
不动后端 / 数据库 / 插件（仍 0.2.32）；`dist/` 已重建，静态部署需重新分发。

用户圈了 `/usage` 两处：①「按天」是一个铺满整宽的巨大粉色矩形；
②「最近 50 次」列表一整坨。放大裁剪确认后分别处理。

**① 柱状图撑成色块（确定 bug）**：`.day` 用 `flex: 1 0 30px`，
只有 1 天有数据时唯一一根柱子 `flex-grow: 1` 撑到容器整宽；
`.day-fill` 又是 `height: tokens/maxDay*100%`，单日恒为 100% 满高，
于是变成 350×62 的实心色块，完全不像柱状图。

修法：`flex: 1 1 34px` + `min-width:30px` + **`max-width:48px`**，
少天数限宽、多天数横向滚动；`.days` 保持 `justify-content: flex-start`
——**不要用 space-between/center**，内容溢出时它们会把左侧柱子裁掉且滚不回来。
柱子高度 62px 不变。

**② 明细列表**：接口仍按 `limit=50` 一次拉齐，但页面默认只铺 `VISIBLE_ROWS = 12` 条，
加「展开全部 N 条 / 收起」按钮，标题由「最近 50 次」改为「最近调用」并标注总数。
另把 `.row` 的 `align-items: center → flex-start`：原来右侧数字落在
「主标题 / 副标题」两行中间，密集列表里每行看着都像错位；改成与主标题齐平
（`.row-tokens` 补 1px 微调）。空列表补了「这个时间窗还没有调用明细」。

**文档**：`design/api_contract.md` §17.6 补前端展示约定（含「单日柱子限宽 48px、
别靠 flex-grow 撑成色块」）、`design/design_overview.md` §5.5 表格同步
「默认 12 条可展开到 50 条」。接口形状与后端完全未动。

**验证**：`npm run build`（含 `vue-tsc`）通过；纯前端，`dist/` 已重建，
插件仍 0.2.32。第二处是按放大图推断的「太长 + 数字没齐平」，
若用户指的是别的具体问题需再对齐。

## 「最近调用」贴边框：回到全局 .rows / .row（第六轮截图反馈）

用户圈了整个明细区：「还是不好看，而且文字都贴着边框了」。
回看截图 + 全局样式后，发现上一轮只处理了「行数 / 数字齐平」，
没碰到真正的根因，而且此前推断「列表没有卡片包裹」是错的。

**真实根因**：`style.css` 本来就有全站列表规范——
`.rows` = 纸片卡片（1px 发丝线 + `--r-lg` 圆角 + `--card` 底 + `overflow:hidden`），
`.rows > li + li` = 行间 `border-top`，`.row` = `display:flex; align-items:center;
gap:12px; min-height:58px; padding:13px 16px`。
但 `UsageView.vue` 的 scoped 样式把 `.row` 覆盖成
`padding: 10px 0; align-items:flex-start; border-bottom:1px solid var(--hairline)`：
**横向 16px 内边距被抹掉** → 文字贴卡片边框；
**又叠了一条 `border-bottom`** → 与全局 `li + li` 的 `border-top` 叠成通栏粗线。
所以在 `.rows` 外面再包一层 `.card` 是错的做法（会双边框），正解是删掉这些覆盖。

**改法**（`QQMessageAssistantVue/src/views/UsageView.vue`）：
- `.row` scoped 只保留 `align-items:center; gap:12px; min-height:54px;
  padding:10px 16px; cursor:default`，**不再写 border-bottom**；
- 行间线交回全局 `li + li` 的 border-top；
- 右侧改成「数字 + `tokens` 单位」右对齐统计块（`.row-tokens` grid + `min-width:58px`），
  整体垂直居中——补上单位后它是完整一列，居中是刻意排版而不是「数字飘在两行中间」；
- 标题加重到 13.5px/500、副行 11px，新增 `rowMeta(row)` 供文案与 `title` 共用；
- 栏目名后加 `<span class="num">N 条</span>`，直接复用全局
  `.block-title .num`（`order:2` 衬线数字 + 发丝引导线），不要自造 `.block-count` 覆盖字重；
- 「展开全部 / 收起」从卡片外那块独立描边按钮改为 `.rows` 的最后一个 `<li class="row-more">`；
- 删掉与标题重复的「共 N 条」脚注。

**验证**：`npm run build`（含 `vue-tsc`）通过。另用系统 Edge + 项目内 playwright
渲染静态复刻页（引用构建后的 `index-*.css` / `UsageView-*.css`，带编译后的 `data-v-*`），
读计算样式确认 `.row` padding = `10px 16px`、`border-bottom: 0px`、
`.rows` border/radius/bg 均生效，并截图目视确认留白、成列数字、末行按钮。
**坑**：Vue scoped id 随源文件内容变化，复刻页的 `data-v-*` 与 CSS 文件名要随新构建同步。

**文档**：`design/api_contract.md` §17.6 补「必须复用全局 `.rows`/`.row`、
不得把横向 padding 改成 0、不得再叠 border-bottom」的硬约束；
`design/design_overview.md` §5.5 表格同步。纯前端改动，后端 / 数据库 / 插件都不动。

## /usage 增加「花在哪个会话」占比饼图（用户第七轮需求）

**需求**：「用量展示中还需要展示具体哪一个聊天消耗的 token，做一个饼状图，比较哪个聊天消耗占比大」。
先摸清写入侧：`token_usage.chat_id` 已存在，但**只记群号**——digest / 群聊自动回复带群号，
`ask` / `extract` / `recap` / 私聊自动回复一律传 `chatId = null`；账本没有 `kind` 列，
所以不同私聊对象暂时分不开。为避免口径返工，结构化确认两点：
① 无 `chatId` 的调用 → **单列一块**；② 会话很多 → **前 6 + 其它**。

**后端**（不新增端点、不改表、不改插件）：
- `TokenUsageMapper#selectByChat`：`GROUP BY u.chat_id`，LEFT JOIN `chat_alias` /
  `chat_setting` 且**必须带 `kind='GROUP'`**，否则「群号恰好等于某人 QQ」时私聊别名会串进群聊桶；
  逗号串不在 SQL 切，Java 侧按 `NAME_SPLIT`（与 `utils/name.ts#firstSegment` 同源）取第一段；
  `MAX()` 只为满足 ONLY_FULL_GROUP_BY（两表 `(chat_id, kind)` 唯一键，一个群最多命中一行）。
- `TokenUsageService#chatBuckets`：`chat_id IS NULL` → `kind=unassigned`「未归属会话」；
  真实群聊按 tokens 降序取 `TuningDefaults.TOKEN_USAGE_CHART_TOP_N = 6`，
  其余合并 `kind=other`「其它 N 个会话」；**两块非真实会话不参与 Top N 竞争**；
  0 token 分组跳过；最终整组再按 tokens 降序排，颜色分配才稳定。
- `TokenUsageSummaryVO` 加 `List<TokenUsageChatVO> byChat`；新增 `TokenUsageChatVO`
  （`chatId / label / kind / calls / tokens`）。**只给 tokens/calls，不返回浮点占比**，
  前端按扇区之和算，以后改 Top N 不用动接口。
- 新增 3 个单测（含驱动别名大小写归一、0 token 跳过、空数据），Java 全量
  `442 / 442`（60 类，0 failure / 0 error）；`selectByChat` 在真实 MySQL 集成测试日志中确认执行。

**前端**（`UsageView.vue`）：不引图表库，SVG `<circle>` + `stroke-dasharray` /
`stroke-dashoffset` 画甜甜圈（`DONUT_R=45`、`DONUT_GAP=2.2` 扇间留纸色），
`transform="rotate(-90 60 60)"` 从 12 点起画，圆中心放总量。
扇区/图例用 `hoveredSlice` 联动透明度；图例**复用全局 `.rows` / `.row` 卡片**（上一轮的教训），
只加一颗 `.legend-swatch`。配色：真实群聊走纸墨色系 `#d92e73 → #88806f` 六档，
`unassigned` 冷灰 `#a8a49d`、`other` 浅暖褐 `#c6b49c`。
**第一版 `other` 太浅、和纸底融在一起**，调深后重建并重渲染确认。
`chatSlices` 里 `length = max(0.8, raw - GAP)`，小扇区不会消失；
`offset` 累加的是 `raw`（未扣 GAP），扇区起点才不会漂。

**验证**：`npm run build` 通过，`dist/` 已重建（产物 `UsageView-*.js` 含最终配色）；
用系统 Edge + playwright 静态复刻页渲染 8 扇（6 群 + 未归属 + 其它），
截图目视确认颜色分层、图例对齐、文字留白；文档相对链接 27 篇 / 83 个 / 0 断链。
